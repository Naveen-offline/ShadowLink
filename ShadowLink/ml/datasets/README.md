# ShadowLink training dataset

`hostnames.csv` is generated by `python -m ml.preprocessing --download` (or from local copies with
`--phish` / `--benign`). Columns: `host` (the entry's **registered domain**), `label`.

## Sources

| Class | Label | Source | License / terms |
|-------|-------|--------|-----------------|
| Phishing | `1` | [mitchellkrogza/Phishing.Database](https://github.com/mitchellkrogza/Phishing.Database), file `phishing-links-ACTIVE.txt` (a community-maintained list of URLs reported as phishing and still active when compiled) | MIT License (stated in the repository's `LICENSE`) |
| Benign | `0` | [zer0h/top-1000000-domains](https://github.com/zer0h/top-1000000-domains), a rank-ordered list of popular domains | The repository has no license file; verify terms before redistributing the data. Only the derived hostname sample is kept here. |

## Preparation

1. Extract the hostname from every phishing URL, then reduce every entry (both classes) to its registered
   domain using the Public Suffix List.
2. Remove duplicate domains and domains present in both lists (ambiguous, e.g. phishing pages hosted on
   popular sites such as `docs.google.com`).
3. Sample 60,000 phishing and 60,000 benign domains (benign from the top 120,000) with seed 42.
4. Split 60/20/20 into train/validation/test **grouped by registered domain**, so related entries never
   appear in more than one split.

### Why registered domains only (a bug that was found and fixed)

The first version trained on full hostnames. The benign list contains only bare registered domains
(0% start with `www.`; 11% have a subdomain) while phishing hostnames usually carry subdomains (69% have two
or more dots). The model learned "has a subdomain => phishing": it scored `www.google.com` at 0.98 and
`docs.python.org` at 0.93, and its headline test metrics (F1 0.82, ROC-AUC 0.91) mostly measured the
difference between the two sources, not phishing. Training and predicting on the registered domain removes that
shortcut. Metrics dropped to the (lower, more honest) figures in `ml/models/model_metadata.json`.
Subdomain structure is still reported by the explainable rule-based indicators.

## Limitations (read before citing any metric)

- Labels are weak: a URL's presence on a community list is not verified ground truth, and some phishing
  hostnames are compromised legitimate sites or shared hosting (e.g. free subdomain services).
- The benign class is *popular* domains, which differ from phishing hosts in many ways unrelated to
  phishing (age, popularity, length). Metrics measured on this sample will overstate real-world accuracy.
- Only registered-domain features are used, because the two sources differ in form (full URLs vs. bare
  domains). The model cannot see subdomains, paths, queries, page content or reputation.
- Even after this fix the two classes still differ in ways unrelated to phishing (popular domains tend to be
  short and well known), so measured performance probably still overstates real-world performance.
- The phishing list is a snapshot in time; retrain periodically.
